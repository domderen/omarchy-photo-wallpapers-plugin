# Optional Mac metadata helper setup

Install current uv (0.13.6 or later) and keep this repository in a stable location. Run `uv python install 3.13.18`, then `uv sync --extra bridge --frozen`. The checked-in runtime pin and package metadata require managed Python >=3.13.18,<3.14. The Rust Omarchy application does not need this helper or Python; OSXPhotos is isolated behind a Darwin marker.

The helper supplies named People, local album membership and exact cloud-master mapping. Omarchy obtains catalog/photo bytes directly from Apple; no helper connection is needed for basic setup or cloud sources. The default `legacy_media: false` mode publishes metadata only: it neither exports nor decodes photo files. Retired catalog/media routes return HTTP 410 in this mode.

Initialize with `.venv/bin/photo-bridge init`, optionally `--library '/path/Library.photoslibrary'`. Configuration and the token live under `~/Library/Application Support/Omarchy Photo Bridge/` with private permissions. Initialization does not publish to the internet. Allow macOS Photos and file-access prompts normally. An updated Python executable can need a new Photos approval even when the previous runtime was approved; wait for and complete the normal prompt. Do not change account-security settings or edit the privacy database.

Run `scripts/install-mac-helper`. It validates a consistent metadata snapshot before installing its dedicated user LaunchAgent and Tailscale Serve HTTPS port 8443. Image-export validation runs only in the explicit legacy mode. Existing listeners are preserved; choose another `https_port` in the private configuration if it is occupied. Tailscale must be running and its account must support HTTPS certificates (MagicDNS/HTTPS in tailnet DNS settings). No public Funnel or automatic access-policy changes are used. The helper binds only 127.0.0.1:8741, with bounded HTTP concurrency, backlog and incomplete headers. Serve restricts access to the tailnet; the bearer token authenticates the client. Tailnet administrators can further restrict the listener to the intended host.

Provision a private pairing file with `.venv/bin/photo-bridge pair --helper-url https://YOUR-MAC.YOUR-TAILNET.ts.net:8443 --output .local/pairing.json`. Transfer the file securely and use `omarchy-photo-wallpapers pair --stdin-json < pairing.json` on the client, or paste its values into the native widget. Never put the token in arguments, shell.json, Git, screenshots, or support reports. Delete the transferred pairing copy when provisioned.

Metadata is checked at startup and every 15 minutes. Unchanged-library checks and a restart with a valid saved result reuse the previous enrichment; extraction runs in a short-lived subprocess when the library changes. `.venv/bin/photo-bridge refresh` checks manually; add `--force` to extract again. `.venv/bin/photo-bridge status --json` reports the last successful refresh, mode and errors. Permission probes time out after 60 seconds; a permission failure preserves the last valid result. A changed-library extraction can take several minutes for a large library.

`launchctl kickstart -k gui/$(id -u)/net.domderen.photo-bridge` restarts the helper. Foreground operation is `.venv/bin/photo-bridge serve`; stop an installed instance first to avoid a port conflict. The Mac must be logged in and awake for new enrichment; Rust clients keep downloading directly from Apple while it sleeps and retain last-known enrichment.

Legacy catalog/image delivery is retained only for explicit rollback compatibility. Enable `legacy_media: true` in the private configuration only if an older client needs it. This mode requires a locally available visible image for installation validation and uses more resources. JPEG and PNG remain supported. HEIF decoding fails closed unless the loaded libheif is >=1.23.7; the pinned pillow-heif wheel currently bundles 1.23.6, so its HEIF path stays disabled. This restriction does not affect metadata-only operation or the Rust client's direct Apple downloads with a supported system libheif.

Update the stable checkout, install its pinned managed Python if needed, run `uv sync --extra bridge --frozen`, then restart the LaunchAgent. Preserve the private configuration, token and ownership file during updates. A new interpreter may need the normal Photos approval again. `scripts/uninstall-mac-helper` removes only this helper's startup job and unchanged owned Serve listener, preserving private data. Add `--purge` to remove its known private data too. `.venv/bin/photo-bridge stop` performs the same owned shutdown without purging; reinstall with `scripts/install-mac-helper` to resume. Never use a global Serve reset for this project.
